# 演示脚本 — 短剧 Web APP（里程碑 7 交付物）

| 项目 | 内容 |
|---|---|
| 用途 | 现场演示动线 + 话术 + 兜底预案，供评委演示时照念/掐表 |
| 总时长 | 约 6~8 分钟（含讲解） |
| 前置条件 | 本机 mysqld 运行中；三端口 8080/3000/3001 空闲；库为种子态（6 剧/24 集/2 账号） |
| 演示账号 | C 端 `demo / demo123`；后台 `admin / admin123` |

---

## 0. 开场（30 秒）

> 「这是一个仿红果短剧的简化版竖屏短剧 Web APP。后端 Java + Spring Boot，前端 React，数据库 MySQL，前后端与数据库真实打通，没有一行 mock。全部媒体资源在本机，断网也能完整演示。」

配套动作：打开 README 顶部的 Mermaid 架构图（或口头描述）：浏览器 → C 端 web:3000 / 后台 admin:3001 → 经 Vite 代理 → 后端 api:8080 → MySQL + 本地 uploads。

一句话设计思路备选（评委问「为什么这么设计」时用）：
- 前后端分离 + JWT 无状态鉴权，免 session 存储；
- 文件存储走 `StorageService` 抽象，本期本地磁盘，未来一行配置切 OSS；
- 点赞收藏用 `(user_id, drama_id)` 唯一索引兜底幂等，并发双击不重复计数。

## 1. C 端浏览（约 1 分钟）

| 步骤 | 操作 | 讲解点 | 预期 |
|---|---|---|---|
| 1.1 | 打开 http://localhost:3000 | 「首页推荐流，数据来自后端 `/api/dramas`」 | 6 部剧封面网格，分类角标、点赞数、集数齐全 |
| 1.2 | 顶部搜索框输「豪门」 | 「300ms 防抖即输即搜，后端模糊匹配」 | 只剩《闪婚老公是豪门》1 部 |
| 1.3 | 清空搜索，点「甜宠」分类 | 「分类筛选与搜索可叠加」 | 剩 2 部甜宠剧 |

**兜底**：搜索无结果属正常口径（空态文案「没有找到相关短剧」）；接口挂了直接 `curl localhost:8080/api/dramas` 给评委看 JSON。

## 2. 注册登录 + 互动（约 1.5 分钟）

| 步骤 | 操作 | 讲解点 | 预期 |
|---|---|---|---|
| 2.1 | 点任意剧进详情，未登录点「点赞」 | 「未登录互动会引导登录并带回跳」 | 跳 `/login?from=/drama/1` |
| 2.2 | 登录页点 demo 快捷填充 → 登录 | 「JWT 签发，前端持久化」 | 自动回跳详情页，顶栏显示「演示用户/退出」 |
| 2.3 | 详情页点「♥ 点赞」「★ 收藏」 | 「幂等切换写库，计数实时变」 | 按钮变已赞/已收藏，计数 +1；刷新状态保持 |

**兜底**：点赞计数可用 `SELECT like_count FROM drama WHERE id=1` 现场交叉验证「真实打通」。

## 3. 播放页核心体验（约 2 分钟，演示主线）

| 步骤 | 操作 | 讲解点 | 预期 |
|---|---|---|---|
| 3.1 | 详情页点第 1 集进播放页 | 「竖屏 9:16 沉浸播放，原生 video」 | 视频播放，宽屏下竖屏居中不拉宽 |
| 3.2 | 滚轮下滑 / 键盘 ↓ 切集 | 「滚轮、键盘、触摸滑动三种切集」 | 切到下一集，URL `?ep=` 同步 |
| 3.3 | 等当前集播完 | 「自动连播」 | 自动进下一集并播放 |
| 3.4 | 看几秒后**直接关掉标签页，重新打开该剧**（不带 ?ep=） | **「记忆续播——进度每 5 秒上报服务端。这是前后端真实打通的现场证据。」** | 自动从上次的集数与秒数续播，弹「已为你续播到第 X 集」 |
| 3.5 | 拉出/看选集区 | 「看过的集带 ✓ 已看标记，当前集高亮」 | 已看集右上角 ✓，当前集玫瑰红 |

**兜底**：自动连播被浏览器拦时会叠「▶ 继续下一集」按钮（正常行为，点一下即可）；续播若没触发，检查是否带了 `?ep=`（显式 ep 时 URL 优先不续播，属设计口径）。

## 4. 个人中心（约 45 秒）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 4.1 | 顶栏「我的」→「观看历史」 | 列表显示「看到第 X 集 · m 分 s 秒 · 刚刚」，点击整条直接续播 |
| 4.2 | 返回「我的」→「我的收藏」 | 刚才收藏的剧在列，点击回详情 |

## 5. 管理后台（约 1.5 分钟，收尾高潮）

| 步骤 | 操作 | 讲解点 | 预期 |
|---|---|---|---|
| 5.1 | 开 http://localhost:3001，先用 `demo/demo123` 登录 | 「前台账号无后台权限，前后端双重鉴权」 | 提示「该账号无后台权限」拒入 |
| 5.2 | 改 `admin/admin123` 登录 | 「独立后台工程，仅管理员」 | 进短剧列表，6 行 |
| 5.3 | 「新增短剧」：填剧名/简介/分类，**本地上传封面** → 提交 | 「文件三重校验（扩展名/大小/文件头），落本地磁盘返回可访问 URL」 | 新增成功，列表 +1 |
| 5.4 | 进该剧「剧集管理」上传一段 mp4 | 「视频上传后时长元数据自动读取」 | 剧集 +1，时长自动填 |
| 5.5 | 回 C 端首页刷新 | 「后台改动前台实时生效」 | 新短剧出现在首页 |
| 5.6 | 后台对该剧点「下架」→ C 端刷新；再「上架」 | 「下架前台隐藏但保留数据」 | C 端消失 → 恢复 |
| 5.7 | 点「删除」二次确认 | 「级联清理点赞/收藏/进度/剧集」 | 后台与 C 端均消失 |

**兜底**：上传超 50MB 或伪装后缀会被 400 拦截（可现场演示「txt 改 .mp4 后缀被拒」体现安全意识）；演示后记得把演示剧删掉回种子态。

## 6. 收尾话术（15 秒）

> 「从浏览、注册登录、点赞收藏，到沉浸式播放、记忆续播，再到后台完整的内容增删改查，整条链路前后端与数据库真实打通。谢谢。」

## 已知的正常口径（评委可能问起，提前对齐）

- 演示剧若被下架，观看历史里仍保留条目并带「已下架」角标（历史是用户私有数据）。
- 播放页显式带 `?ep=N` 时以 URL 为准，不触发记忆续播（防止「想重看某集却被跳走」）。
- 已看标记是推断式（当前进度集之前的集视为已看），非逐集精确记录——每剧只存一条最新进度的数据模型决定。
