## 一、本阶段目标

验收标准一句话：**断网冷启动后三服务一键拉起，C 端用户链路与管理后台链路按演示脚本全流程走通无卡点，README 与实际能力一致，演示脚本成文且经掐表演练，库回到干净种子态。**

达成后 PRD 第十章 7 个里程碑 100% 收口，项目进入「可随时现场演示」状态。

## 二、本阶段性质：零新功能

本阶段不写任何新功能代码。全部工作分三类：

1. **验证**：把已有能力按演示路径完整走一遍，每一环留实证。
2. **彩排**：演示脚本成文 + 掐表演练。
3. **文档**：README/devlog/AGENTS.md 回填至最终态。

## 三、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 走查执行方式 | **能自动化的全自动化**（curl + 浏览器自动化），真人演练单独列为用户任务 | 自动化走查留实证、可重复；真人彩排的手感/话术只能用户本人做 |
| 断网验证方式 | 沿用阶段3 口径：**资源审计代验**（关键页 performance 条目全部本机来源 + 源码 grep 无外链），不真拔网线 | 真拔网线会打断施工会话本身；资源审计等价且可自动取证 |
| 后台走查的破坏面 | 新增→编辑→剧集上传→下架→上架→**删除收尾**，走查后库回种子态 | 删除链路是 AD-04 验收点必须走；走完即清理，演示前库保持 6 剧/24 集/2 账号 |
| 缓存观察项处置 | 走查中重点观察「换页后 10s 内已看标记/历史是否陈旧」；**复现才修**（一行 `Cache-Control: no-store`），不复现则记录关闭 | 阶段5 偏差3 未能稳定复现，预防性改动违反「本阶段不动代码」原则 |
| 测试账号清理 | 删除 `gateuser`、`browser_demo`（阶段2 门禁副产物），走查新造的账号一并清理 | devlog 阶段2 已附 SQL；演示前库应只含种子账号 |
| 演示脚本存放 | `docs/demo-script.md` 独立成文，README 加链接 | 脚本含话术与掐表，与 README 的「快速开始」职责不同 |
| 裁剪预案 | 若时间紧：三档截图从简（阶段2 验过且后续改动小）；**断网审计、续播演示、后台 CRUD 演示、README 回填四项不砍** | 四项是演示生命线 |

## 四、工作拆解

### 任务 1：质量门禁 + 冷启动

- `./mvnw test`（35 例）、web 与 admin `pnpm exec tsc -b` 三项全绿。
- `scripts/dev.sh` 一键拉起三服务，`/api/ping` 200，三端口在线。
- 资源审计：首页/播放页/后台列表三关键页 performance 条目全部本机来源；前端源码 grep 无外链（断网演示安全）。

### 任务 2：C 端用户链路走查（demo/demo123）

注册新账号 → 登录 → 首页搜索（「豪门」命中 1 部）+ 分类筛选 → 详情页点赞收藏（写库、计数变化）→ 播放页：进度上报 → 重进续播（集数与秒数恢复、提示出现）→ 键盘/滚轮切集 → 自动连播推进 → 选集已看 ✓ 标记 → 观看历史页（倒序、点击续播）→ 我的收藏 → 退出登录。

### 任务 3：管理后台链路走查（admin/admin123，:3001）

demo 登录被拒（非 ADMIN）→ admin 登录 → 短剧新增（封面真实上传）→ 编辑剧名（C 端实时变）→ 剧集上传（时长自动读取）→ 下架（C 端消失）→ 上架（C 端恢复）→ 删除（Popconfirm + 级联清理归零）。

### 任务 4：缓存观察项复验 + 三档响应式

- 改库进度 → 10s 内换页观察已看标记/历史是否陈旧；复现则加 `Cache-Control: no-store` 并重验，不复现记录关闭。
- 375 / 900 / 1440 三档截首页 + 播放页，确认无错位无横向滚动（阶段4/5 动过这两页，需回归）。

### 任务 5：清理与种子态恢复

- 删除走查数据（演示剧、剧集、上传文件解引用、进度/点赞/收藏归零）。
- 删除测试账号 `gateuser`、`browser_demo` 及本阶段新造账号。
- 终态核对：6 剧 / 24 集 / 2 账号（admin、demo），0 like / 0 fav / 0 progress。
- 关停三服务，端口释放。

### 任务 6：演示脚本 `docs/demo-script.md`

结构：开场 30s 定位（仿红果竖屏短剧 + Mermaid 架构图）→ 演示动线 5~8 分钟（首页搜索/分类 → 详情点赞收藏 → 播放切集连播 → **记忆续播作为「前后端真实打通」的现场证据**（PRD PL-04 指定讲解点：关掉标签页重开进度还在）→ 观看历史/我的收藏 → 后台增删改查 + C 端实时生效收尾）→ 每步兜底预案 → 设计思路讲解要点（StorageService 抽象、幂等互动唯一索引、JWT 无状态、JPA 建表 + 空库种子自动灌入）。
