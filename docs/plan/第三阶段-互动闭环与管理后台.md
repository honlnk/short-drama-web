## 一、本阶段目标

验收标准一句话：**demo 账号在详情页点赞、收藏真实写库且刷新后状态仍在，「我的」页能看到收藏列表；admin 账号登录后台完成「新增一部短剧 + 上传封面 + 加一集视频」，C 端首页与播放页立刻可见可播。**

达成后，题目规定的全部必含功能（注册/登录、内容展示、点赞、收藏、管理后台增删改查）100% 集齐，项目达到「即使砍掉里程碑 6 也完整可交付」的状态；剩余工作（切集手势、连播、续播、历史、搜索、彩排）全部为体验加分项。

## 二、为什么 4+5 合并（已拍板）

- 里程碑 4 体量单薄：第二阶段已把鉴权规则（`/api/dramas/*/like` 等需登录）、`FavoriteRepository` / `UserLikeRepository`、详情页按钮 UI 与状态回显全部备好，M4 实际是「写库填坑」，单独成阶段立不起一份计划的门禁分量。
- 两个里程碑共享同一批后端基础：统一响应包体 `{code,message,data}`、全局异常处理、SecurityConfig 鉴权规则均在第二阶段就位，拆开做会重复过一遍「接口规范对齐」流程——与 M2+M3 合并同款逻辑。
- 演示叙事连贯：「用户侧互动写库」+「运营侧后台造内容」是「前后端真实打通」的一体两面，合并收口后演示脚本可以当场双向验证（前台点赞 → 数据库可查；后台新剧 → 前台可见）。

## 四、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 点赞/收藏语义 | **幂等切换**：已赞再调 = 取消，返回最新状态 `{liked: true/false}`；收藏同构 | PRD IN-01/02 明文「幂等切换」；前端单按钮来回切，无需两个端点 |
| 幂等兜底 | 数据库唯一索引 `(user_id, drama_id)` 兜底并发/重试，捕获 `DataIntegrityViolationException` 按「已存在」处理 | PRD §6 约束说明已定；唯一索引第一阶段建表时已随实体落地 |
| like_count 维护 | 点赞/取消时同事务 `drama.like_count ± 1`，下限 0 | 首页与详情展示的就是这个冗余字段，必须随写库同步；事务保证不出负数 |
| 收藏列表 | `GET /api/me/favorites` 返回 DramaSummary 列表（复用首页 DTO），按收藏时间倒序 | IN-03；复用 DTO 不新造结构，前端收藏页卡片与首页同款 |
| 观看进度/历史 | **本阶段不做**（PL-04/05 属里程碑 6），`PUT /api/me/progress`、`GET /api/me/history` 端点不建 | 明确边界；WATCH_PROGRESS 表已存在但本阶段不写不读 |
| StorageService 落地 | 接口 `store(MultipartFile, subdir)` / `delete(url)` / `getUrl(path)`；`LocalStorageService` 写 `apps/api/uploads/files/`，URL 形态 `/uploads/files/<uuid>.<ext>` | PRD §7.3（2026-10-16 修订）：与种子媒体同目录同映射单轨制；uuid 文件名避免碰撞与中文名问题 |
| 上传校验 | 封面：jpg/jpeg/png/webp，≤5MB；视频：mp4，≤50MB；类型白名单 + 大小上限，超限返回明确错误 | 演示规模够用；白名单防止任意文件上传，现场讲解可提「安全意识」 |
| 后台短剧删除 | **二次确认 + 级联清理**：删除剧时同事务删除其剧集、点赞、收藏、观看进度记录；被引用的媒体文件**不删磁盘**（仅解引用） | PRD AD-04「级联处理」；种子媒体文件被多集共享引用，误删文件会破坏其他数据，演示期保留文件最安全 |
| 下架语义 | `status=OFFLINE` 时 C 端详情/剧集接口返回 404（第二阶段已实现的口径），列表接口本就不返回；后台列表照常可见可编辑 | PRD AD-04「下架剧前台隐藏但保留数据」；与第二阶段详情接口行为一致 |
| 剧集删除 | 允许删除任意集；删除后**不自动重排**集数，由管理员在编辑表单里自己维护 `episodeNo`（加唯一约束 `(drama_id, episode_no)` 防重复） | 排序交互（拖拽/上移下移）是 PRD 裁剪预案明示可砍的「次要交互」；唯一约束保住数据底线 |
| 后台登录 | 独立登录页走同一个 `POST /api/auth/login`；前端校验 `user.role === 'ADMIN'` 才放行进入，非管理员提示「无后台权限」并登出 | PRD 5.2「仅接受管理员角色令牌」；后端 `/api/admin/**` 的 ROLE_ADMIN 才是硬闸门，前端校验只是体验层 |
| 后台 token | 与 C 端同一 localStorage key 体系**隔离**：后台用 `admin_token`，互不串登录态 | 两工程不同端口本就不共享存储，但同浏览器演示时 key 隔离让「C 端 demo、后台 admin」双线并存不互踢 |
| 后台技术栈 | Ant Design 5：`Layout` + `Table` + `Form` + `Upload` + `Modal` + `message`，不做视觉定制，仅 PC | PRD 5.2 明文口径；演示重点在「真实 CRUD」不在颜值 |
| 分页 | 后台短剧列表服务端分页（`page`/`size`，默认 size=10）；C 端收藏列表数据量小，全量返回不分页 | PRD §9「列表接口加分页即可」；收藏演示最多个位数记录 |

## 五、工作拆解

### 任务 1：后端互动接口（里程碑 4 后端）

1. **点赞/收藏切换**（`InteractionController` 或并入 `DramaController`，实现时自选并在交付说明记录）：
   - `POST /api/dramas/{id}/like`：需登录。查 `user_like` 存在则删记录、`like_count - 1`（下限 0）、返回 `{liked:false, likeCount}`；不存在则插记录、`like_count + 1`、返回 `{liked:true, likeCount}`。整段 `@Transactional`，剧不存在或 OFFLINE → 404。
   - `POST /api/dramas/{id}/favorite`：同构，返回 `{favorited: true/false}`（收藏无计数展示需求，不返 count）。
   - Repository 增补：`UserLikeRepository.deleteByUserIdAndDramaId`、`FavoriteRepository.deleteByUserIdAndDramaId` 与 `findByUserIdOrderByCreatedAtDesc`。
   - 唯一索引冲突（并发双击）捕获后按最终状态返回，不抛 500。
2. **我的收藏列表**：`GET /api/me/favorites` 需登录，按收藏时间倒序返回 DramaSummary 列表（字段与首页一致：id/title/category/coverUrl/episodeCount/likeCount）。
3. **回归**：详情接口的 liked/favorited 回显此时应为真实数据——种子用户 demo 的点赞收藏写库后，`GET /api/dramas/{id}` 带 demo token 回显 true。

**门禁（curl 全绿）**：
- 无 token 调 like/favorite/favorites → 401 JSON（第二阶段鉴权规则已配，此处验证生效）。
- demo token 点赞剧 1 → `{liked:true, likeCount:+1}`；再调一次 → `{liked:false, likeCount:回原值}`；连续并发双击不产重复记录（查库验证）。
- 收藏剧 1、剧 2 后 `GET /api/me/favorites` → 2 条、倒序正确。
- 写库后带 token 查详情 → liked/favorited 与操作一致；退出再查（不带 token）→ false。
- `./mvnw test` 全绿（为切换逻辑补 Service 层单测：切换往返、唯一索引冲突路径）。

### 任务 2：前端互动闭环（里程碑 4 前端）

1. **详情页按钮接通**（`DramaDetailPage`）：
   - 已登录点击点赞/收藏 → 调接口，用响应 `{liked, likeCount}` / `{favorited}` 直接更新本地状态（不发二次详情请求）；失败 `message` 提示并回滚。
   - 未登录点击 → 跳 `/login?from=/drama/{id}`（沿用第二阶段 401 拦截器的 from 回跳口径）。
   - 替换第二阶段「里程碑 4 实现」占位提示——**该占位文案随本任务删除，不并存**。
2. **「我的」页与收藏列表**：
   - 路由：`/mine`（MinePage，需登录，用第二阶段备好的 `RequireAuth` 守卫）、`/mine/favorites`（我的收藏）。
   - MinePage：展示当前用户信息（username/nickname/role）+ 入口卡片「我的收藏」+「退出登录」按钮（US-04：清 token 跳首页，退出后点赞收藏重新要求登录）。
   - FavoritesPage：调 `/api/me/favorites`，卡片网格复用首页卡片样式，点击进详情；空态文案「还没有收藏，去首页逛逛」；未登录被守卫拦到登录页。
   - 导航：首页顶部（PC）/底部 Tab（手机，按 PRD 5.3 断点规则）加「我的」入口，未登录点击同样进守卫流程。

**门禁**：
- demo 登录 → 详情页点赞（按钮态与计数即时变化）→ 收藏 → 刷新页面状态仍在 → `/mine/favorites` 见该剧 → 详情页再次点击取消收藏 → 收藏列表为空态。
- 未登录点收藏 → 跳登录页 → 登录成功自动回跳详情页。
- 退出登录 → 点赞按钮回到未登录引导态。
- `pnpm exec tsc -b`（web）通过。

### 任务 3：后端管理接口 + StorageService（里程碑 5 后端）

1. **StorageService**（`storage/` 包）：
   - **先做前置配置**：application.yml 显式配置 `spring.servlet.multipart.max-file-size=50MB`、`spring.servlet.multipart.max-request-size=50MB`（Spring Boot 默认 1MB/10MB 必拦视频上传，不配则任务门禁必挂）。
   - `StorageService` 接口：`store(MultipartFile file, String subdir)` 返回 URL、`delete(String url)`、`getUrl(String path)`。
   - `LocalStorageService`：落盘 `apps/api/uploads/files/`（启动时 `Files.createDirectories` 保证存在），文件名 `UUID.randomUUID() + 原扩展名`，URL 拼 `/uploads/files/<name>`；类型/大小白名单校验在 Service 入口统一做（封面 4 种图片 ≤5MB，视频 mp4 ≤50MB），不合规抛业务异常（400 + 明确文案）。
   - 配置项 `storage.type=local` 写入 application.yml（仅占位与讲解用，本期无第二实现）。
2. **文件上传接口**：`POST /api/admin/files/upload`（ADMIN，`multipart/form-data`，字段 `file` + `type=cover|video`），返回 `{url}`。
3. **短剧管理**（`AdminDramaController`，全部 `/api/admin/**` + ADMIN）：
   - `GET /api/admin/dramas?page=&size=&keyword=`：分页列表（含 OFFLINE），返回 `Page<AdminDramaRow>`（id/title/category/episodeCount/status/likeCount/createdAt/coverUrl）；keyword 模糊匹配剧名（为后台检索顺手提供，C 端搜索仍是里程碑 6）。
   - `POST /api/admin/dramas`：新增（title/description/category/coverUrl/status 必填校验，coverUrl 须为 `/uploads/` 开头——只允许本服务上传产物的 URL，防外链失效破坏「断网可演示」底线）。
   - `PUT /api/admin/dramas/{id}`：编辑任意字段，同校验。
   - `DELETE /api/admin/dramas/{id}`：同事务级联删 episodes + user_like + favorite + watch_progress；不删磁盘文件。
4. **剧集管理**（`AdminEpisodeController`）：
   - `GET /api/admin/dramas/{id}/episodes`：后台剧集列表（含 videoUrl、durationSec）。
   - `POST /api/admin/dramas/{id}/episodes`：新增（episodeNo/title/videoUrl/durationSec 必填；`(drama_id, episode_no)` 冲突 → 400「集数已存在」）。
   - `PUT /api/admin/episodes/{id}`、`DELETE /api/admin/episodes/{id}`：编辑/删除（同唯一约束；删除不级联文件）。

**门禁（curl 全绿）**：
- admin token 上传一张封面 → 返回 `/uploads/files/<uuid>.jpg`，浏览器（8080 直连与 3000/3001 代理两路）可打开；上传 51MB 假 mp4 → 400 明确提示；上传 `.txt` 改后缀伪装 → 400。
- demo token（USER）调任意 `/api/admin/**` → 403；无 token → 401。
- 新增短剧（用刚上传的封面）→ 后台列表可见、C 端 `GET /api/dramas` 含该剧 → 加两集（上传视频）→ C 端详情/剧集接口可见、播放页可播。
- 编辑剧名 → C 端详情实时变；下架（status=OFFLINE）→ C 端详情 404、列表消失，后台仍可见；再上架恢复。
- 删除该剧 → 后台列表消失，关联剧集/点赞/收藏/进度记录查库确认清空；`uploads/` 下文件仍在（符合决策）。
- 新增剧集 episodeNo 与已有重复 → 400「集数已存在」。
- `./mvnw test` 全绿（StorageService 白名单、级联删除、唯一约束冲突路径各补测试）。

### 任务 4：管理后台前端（里程碑 5 前端，`apps/admin`）

替换占位页，建四个页面 + 基础设施：

1. **基础设施**：axios 实例（baseURL 走代理，拦截器读 `admin_token`、401 清 token 跳登录页）；`AuthContext` 精简版（user/token/login/logout）；路由守卫（无 token 跳 `/login`，user.role≠ADMIN 拒绝进入）。
2. **登录页**：居中卡片表单；登录成功校验 role==ADMIN，非管理员 `message.error('该账号无后台权限')` 并清 token；页面上预填提示 `admin / admin123`（演示友好，与 C 端登录页同风格）。
3. **短剧管理页**（默认页）：AntD `Table` 分页（封面缩略图/剧名/分类/集数/状态 Tag/点赞数/创建时间），顶部「新增短剧」按钮 + 剧名搜索框；行操作「编辑 / 剧集管理 / 下架或上架 / 删除」；删除走 `Popconfirm` 二次确认（PRD AD-04 硬性要求）。
4. **短剧表单页**（新增/编辑共用，`/dramas/new`、`/dramas/:id/edit`）：AntD `Form` 必填校验；封面用 `Upload` 组件直传 `/api/admin/files/upload?type=cover`，成功后回显缩略图并把返回 URL 填入表单；状态下拉 ONLINE/OFFLINE。
5. **剧集管理页**（`/dramas/:id/episodes`）：剧集 `Table`（集数/标题/时长/视频可点预览）+ 新增/编辑弹窗 `Modal`（episodeNo 数字输入、标题、视频 `Upload` 传 `type=video`、上传后自动尝试读视频时长填 durationSec，读不到则手填）+ 删除确认。

**门禁**：
- admin 登录后台 → 走完整演示链：新增短剧（上传封面）→ 加两集（上传视频）→ C 端首页出现该剧、播放页可播 → 后台下架 → C 端消失 → 上架恢复 → 删除（二次确认）→ C 端消失。
- demo 账号登后台 → 明确拒绝并退回登录页；直接访问 `/dramas` 无 token → 跳登录。
- 表格分页翻页正确（种子 6 剧 + 新增可造到 11 条以上翻页）；表单必填校验拦截空提交。
- `pnpm exec tsc -b`（admin）通过。
