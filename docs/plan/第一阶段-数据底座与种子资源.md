## 一、本阶段目标

验收标准一句话：**C 端首页能用后端真实接口渲染出短剧封面网格，数据来自 MySQL，视频与封面全部为本地资源。**

达成后，项目第一次跑通「启动后端 → 启动前端 → 首页看到真实短剧数据」这条演示路径，后续所有功能（登录、点赞、收藏、后台）都建立在这层底座之上。

## 二、与脚手架会话的分工边界

另一个会话正在按既定口径施工三工程骨架（`apps/api` + `apps/web` + `apps/admin`，端口 8080 / 3000 / 3001），本计划**不重复覆盖其工作**，只交付它无法独立完成的三块内容，并与其约定接口：

| 分工 | 负责方 | 交付物 |
|---|---|---|
| 三工程骨架、构建配置、依赖引入 | 脚手架会话 | apps/api、apps/web、apps/admin 可空跑 |
| 数据库建表（JPA 实体） | 脚手架会话 | 启动后自动建出 6 张表 |
| **数据库连接与建库** | 本计划 | `short_drama` 库就绪，连接配置定稿 |
| **种子媒体资源** | 本计划 | 视频 + 封面文件落 `apps/api/uploads/`，含校验脚本 |
| **种子数据内容与灌库** | 本计划 | CommandLineRunner 种子脚本，空库启动自动导入 |

接口约定（双方必须遵守，避免合并冲突）：

- 种子媒体文件统一存放 `apps/api/uploads/` 下：视频 `uploads/videos/`、封面 `uploads/covers/`
- 种子数据中 `video_url` / `cover_url` 字段写**相对路径**（如 `/uploads/videos/drama-01/ep-01.mp4`），由后端静态映射 `/uploads/**` 对外提供
- 种子脚本写在 `apps/api/src/main/java/.../config/DataSeeder.java`，实现 `CommandLineRunner`，以「用户表为空」为触发条件
- 数据库连接配置写在 `apps/api/src/main/resources/application.yml`，账号密码用占位符 `${DB_USERNAME:root}` / `${DB_PASSWORD:}` 支持环境变量覆盖，默认值按本机实际配置

## 三、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 数据库 | 本机 MySQL 26.7（日历版本号体系），3306 直连 | 用户本机已安装运行，免容器、真实持久化 |
| 库名 | `short_drama`（utf8mb4 / utf8mb4_unicode_ci） | 避开本机已有库，utf8mb4 支持全量中文与 emoji |
| 建表方式 | JPA `ddl-auto=update` + 实体注解，不手写 schema.sql | 快速迭代；种子数据用 Java 写入，天然兼容方言 |
| 种子触发 | CommandLineRunner，仅当 `userRepository.count() == 0` 时执行 | 幂等：重复启动不重复灌数据 |
| 媒体来源 | **Mixkit 竖屏素材（360×640，9:16），已下载 50 个至 `seed-assets/videos/`（54MB，2026-10-16 完成，零失败）**；`seed-assets/` 已入 `.gitignore` | 真人实拍竖屏素材，播放页沉浸感成立；直链可 curl，已实测全部可达 |
| 封面来源 | 本地生成 SVG（渐变背景 + 剧名文字），按分类配色 | 零版权风险、零下载依赖、风格统一 |
| 种子规模 | 6 部短剧 × 每部 4 集 = 24 集，覆盖 5 个分类 | 满足 PRD「4~6 部、至少 3 个分类、每部 3~5 集」 |
| 种子账号 | `admin / admin123`（ADMIN）、`demo / demo123`（USER），密码 BCrypt 加密 | PRD SD-01 定稿口径 |
| uploads/ 是否入库 | **不入 git**，`.gitignore` 忽略 `apps/api/uploads/`；重建两步串行：`fetch-seed-media.sh`（下载素材池）→ `allocate-seed-media.sh`（选片复制 + 封面生成），均幂等（2026-10-16 修正：原稿误写「fetch 一键重建」，拆两步可复用素材池） | 二进制 mp4 入库会让仓库膨胀，脚本可复现 |

## 四、工作拆解

### 任务 1：数据库就绪（前置，阻塞脚手架联调）

1. 在本机 MySQL 执行建库：

   ```sql
   CREATE DATABASE IF NOT EXISTS short_drama
     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. 与脚手架会话核对 `application.yml` 中的连接配置（url / 账号 / 密码），确认后端启动能连上、JPA 能自动建出 6 张表（user / drama / episode / favorite / user_like / watch_progress）。

### 任务 2：种子媒体资源（素材已就绪，仅剩分配复制）

前置状态（2026-10-16 已完成）：50 个 Mixkit 竖屏视频已下载至 `seed-assets/videos/`（54MB，ID→标题映射见 `scripts/mixkit-titles.txt`，分类建议见 `seed-assets/README.md`）；下载脚本 `scripts/fetch-seed-media.sh` 可幂等重建。

本任务剩余职责：

1. **按分类选片**：从 50 个素材中为 6 部剧各选 4 集（共 24 个），按 `seed-assets/README.md` 的分类建议匹配（甜宠剧配情侣/泳池类，悬疑剧配黑暗/哥特类，以此类推；空镜转场类可凑数）。「古装」无直接素材，用氛围素材顶替并在演示话术中说明。
2. **复制到 uploads**：按 `uploads/videos/drama-{01..06}/ep-{01..04}.mp4` 目录结构复制选中文件并重命名，使种子数据中的 `video_url` 与文件一一对应。
3. **生成 6 张封面 SVG**：按 `uploads/covers/drama-{01..06}.svg`，每部剧按分类配色生成渐变底 + 剧名文字。
4. **输出校验报告**：统计文件数量、总体积，校验 24 个视频 + 6 个封面全部就位且非空。

门禁：`uploads/` 下 30 个媒体文件齐全；浏览器直接访问 `http://localhost:8080/uploads/videos/drama-01/ep-01.mp4` 可播放（依赖脚手架会话完成静态映射后联调）；断网环境下重跑演示路径无资源缺失。

### 任务 3：种子数据脚本（`DataSeeder.java`）

数据内容（全部中文，贴近真实短剧命名风格）：

| 剧编号 | 剧名 | 分类 | 简介基调 |
|---|---|---|---|
| 01 | 示例：闪婚老公是豪门 | 甜宠 | 契约婚姻、先婚后爱 |
| 02 | 示例：都市之最强狂兵 | 都市 | 兵王回归、扮猪吃虎 |
| 03 | 示例：重生之逆袭人生 | 逆袭 | 重生复仇、商战打脸 |
| 04 | 示例：王爷的替嫁王妃 | 古装 | 替嫁、宅斗、权谋 |
| 05 | 示例：午夜出租车 | 悬疑 | 都市怪谈、连环反转 |
| 06 | 示例：霸总的小娇妻 | 甜宠 | 霸道总裁、误会追妻 |

（剧名可由施工时微调，保持「一眼看出题材」的网文命名风格即可；6 部剧覆盖 5 个分类，甜宠占 2 部。）

每部剧字段：`title`、`description`（2~3 句）、`category`、`cover_url`、~~`status=PUBLISHED`~~ `status=ONLINE`（2026-10-16 修正：以 PRD §6 口径 ONLINE/OFFLINE 为准，原稿笔误）、`like_count` ~~随机 3~4 位数~~ 固定值 963~3258（保证首页排序稳定，演示可预期）；每集字段：`episode_no`、`title`（如「第1集 闪婚领证」）、`video_url`、`duration_sec` ~~按实际素材时长填 5 或 10~~ 按素材真实时长取整填入 8~28（避免播放页时长显示与实际不符）。

账号：`admin`（role=ADMIN）、`demo`（role=USER），密码 BCrypt 加密。

门禁：
- 空库启动：日志出现种子导入记录，`SELECT COUNT(*)` 验证 6 剧 / 24 集 / 2 账号。
- 二次启动：日志显示「数据已存在，跳过种子导入」，记录数不变。
- `curl http://localhost:8080/api/dramas` 返回 6 部剧的 JSON，字段完整。

### 任务 4：首页联调（与脚手架会话会合）

脚手架会话完成 C 端首页骨架后，本计划负责确认首页 `GET /api/dramas` 调通：封面网格渲染 6 部剧，封面、剧名、集数、点赞数均来自接口，无前端写死数据。

- 点赞、收藏功能（里程碑 4；本阶段只建表，不写接口）
