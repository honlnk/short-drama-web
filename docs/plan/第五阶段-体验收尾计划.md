## 一、本阶段目标

验收标准一句话：**demo 账号看过的剧集，在播放页选集区有「已看」标记，当前集高亮；个人中心新增「观看历史」入口与列表页，点击任一条目直接进入播放页并从上次进度续播。**

达成后，里程碑 6（PRD 4.4 观看增强 6 个 PL）100% 收口，PRD 第八章 C 端页面与接口全部集齐；项目剩余工作只剩里程碑 7「联调彩排 + 演示脚本 + README 收尾」。

## 二、为什么这两项合并成一个阶段

| 候选项 | 现状 | 结论 |
|---|---|---|
| PL-05 观看历史前端页 | 后端 `GET /api/me/history` 与前端 `getHistory()` 封装均已就绪（阶段4），纯 UI 工作：一个列表页 + 一个路由 + MinePage 一个入口 | ✅ 并入 |
| PL-03 选集已看标记 | 当前集高亮已有（阶段2）；「已看」标记依赖进度数据推断，数据源同样是 `getHistory()` | ✅ 并入（与 PL-05 共用一次 history 请求思路） |

两项合计工作量约半天，不值得拆成两阶段；且都依赖同一份 history 数据，一次施工顺手把两处都点亮。

## 三、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 已看判定规则 | **推断式**：`episodeNo < 当前进度集 episodeNo` 标为已看；等于当前进度集且 `progressSec >= durationSec - 3`（复用阶段4 片尾阈值）也标已看；大于当前进度集不标。**不加表、不改后端、零数据迁移** | watch_progress 每用户每剧只存一条记录（PRD §6 明文「每部剧只保留最新一条进度」），精确式要加集级观看记录表，后端动表+接口+单测，工作量翻数倍而演示价值不增；短剧按顺序连播是主流观看方式，推断式标记在演示路径下正确 |
| 已看标记视觉 | 已看集按钮右上角叠加小号「✓」角标（或文案「已看」缩角标），当前集保持玫瑰红高亮不变；未登录时所有集无已看标记 | 沿用现有按钮网格，不动布局；与当前集高亮视觉层级分离，不混淆 |
| 选集面板形态 | **保持右侧信息栏常驻网格**，不做「拉出式面板」 | PRD 验收标准是「可拉出选集面板，标记已看/当前集；跳集后播放进度正确」——演示场景常驻区块比抽屉更直观，评委一眼看到选集；此为本阶段对 PRD 措辞的**正式偏差**，记录于此（弹出面板需要遮罩/滑动手势适配三端，工作量与演示收益不匹配） |
| 历史页路由 | `/mine/history`，RequireAuth 守卫（与 `/mine/favorites` 同构），MinePage 导航加「🕐 观看历史」入口（在「我的收藏」上方） | PRD PL-05「个人中心观看历史列表」；入口顺序历史在前因为观看行为比收藏高频 |
| 历史页条目内容 | 横向条目卡：封面缩略图（左）+ 剧名 + 「看到第 X 集 · 第 X 分 X 秒」+ 相对时间（如「2 小时前」，用简单函数格式化，不引第三方库）；点击整卡跳 `/drama/{dramaId}/play`（**不带 `?ep=`**，由阶段4 的记忆续播逻辑自动恢复到记录的集数与秒数） | PL-05 验收标准「点击直接续播」：不带 `?ep=` 正好触发 PlayerPage 既有续播分支，零播放页改动 |
| 下架剧条目 | 保留显示，封面右上角加「已下架」角标，仍可点击（点击后撞详情/播放页 404 提示，属正常口径，后端 HistoryItem 不过滤 OFFLINE 的设计延续） | 阶段4 后端决策「历史是用户私有数据」已定；演示中评委看不到下架剧条目属于正常（种子剧全部在架） |
| 空态文案 | 「还没有观看记录，去首页逛逛」+「回首页」按钮（与 FavoritesPage 空态同构） | 保持个人中心子页视觉一致性 |
| 排序 | 按 `updatedAt` 倒序（后端已倒序返回，前端不二次排序） | 后端契约即最近观看在前 |
| 数据获取 | HistoryPage 进页面拉一次 `getHistory()`；播放页已看标记复用 PlayerPage 续播分支已发出的那次 `getHistory()` 结果（**把续播分支的 items 存入 state 复用**，不为已看标记单独再发一次请求） | 播放页续播分支本来就要拉 history（阶段4 已实现），已看标记用同一份数据，避免重复请求 |

## 四、工作拆解

### 任务 1：观看历史页面（PL-05 前端）

**改动文件（全部在 `apps/web`）：**

1. `src/pages/HistoryPage.tsx`（**新增**）：参照 `FavoritesPage.tsx` 的加载/错误/空态三态结构；条目为横向卡片（`flex`，封面 `aspect-[9/16]` 固定宽 64px 左图右文），文案区三行：剧名（truncate）、「看到第 {episodeNo} 集 · {m} 分 {s} 秒」、相对时间；下架剧封面叠「已下架」角标；整卡 `<Link to={\`/drama/${dramaId}/play\`}>`。相对时间格式化写一个 10 行本地函数（`刚刚 / n 分钟前 / n 小时前 / n 天前 / yyyy-MM-dd`），不引 dayjs。
2. `src/router/index.tsx`：加 `{ path: '/mine/history', element: <RequireAuth><HistoryPage /></RequireAuth> }`。
3. `src/pages/MinePage.tsx`：导航区在「我的收藏」上方加「🕐 观看历史」Link（同款样式）。

**门禁（浏览器自动化实证）：**

- 未登录访问 `/mine/history` → 跳登录页（RequireAuth 行为与收藏页一致）。
- demo 账号造 2 条进度（curl 上报剧 A 第 2 集、剧 B 第 1 集，间隔几秒保证 updatedAt 可分先后）→ 历史页 2 条，剧 A 在前（倒序），条目显示「看到第 2 集 · 0 分 35 秒」（按实际上报值断言）与相对时间。
- 点击剧 A 条目 → 进入 `/drama/{A}/play`（地址栏无 `?ep=`）→ 自动续播到第 2 集并从记录的秒数起播，出现「已为你续播到第 2 集」提示。
- 清空 demo 全部进度（DELETE 或直接改库）→ 历史页空态文案 + 「回首页」按钮可用。
- 后台下架剧 B → 历史页剧 B 条目仍显示且带「已下架」角标；点击后详情/播放页给出不存在或已下架提示。

### 任务 2：选集已看标记（PL-03）

**改动文件（全部在 `apps/web`）：**

1. `src/pages/PlayerPage.tsx`：
   - 续播分支的 `getHistory().then((items) => …)` 中，把 `items` 存入 `historyItems` state（现有逻辑只在未带 `?ep=` 时拉取；**调整为已登录即拉取**，`?ep=` 存在时仍拉数据用于已看标记但跳过恢复跳转）。
   - 派生 `watchedBefore: Set<number>`：取本剧那条记录，将所有 `episodeNo < record.episodeNo` 的集号放入；若 `record.progressSec >= 该集 durationSec - 3`（当前集已看到片尾）则把 `record.episodeNo` 也放入。
   - 选集按钮渲染时，`watchedBefore.has(episode.episodeNo)` 的集右上角叠「✓」角标（`absolute` 定位小圆点或角标，样式参照收藏卡片的黑底半透明角标）。
   - 未登录 / 无 history 记录：Set 为空，零标记，行为与现状完全一致。
2. 无其他文件改动（不动后端、不动路由、不动其他页面）。

**门禁（浏览器自动化实证）：**

- demo 账号 curl 上报剧 A（4 集）第 3 集 5s（durationSec 13s）→ 播放页选集区第 1、2 集带「✓」，第 3 集不带（未看到片尾）、保持当前集高亮，第 4 集不带。
- curl 上报剧 A 第 3 集 13s（=durationSec）→ 第 3 集也带「✓」。
- 从第 1 集自然连播到第 2 集播放 6s（触发 5s 节流上报）→ 刷新页面后第 1 集带「✓」（连播上报更新了进度记录）。
- 显式 `?ep=4` 进入 → 已看标记仍正确显示（标记不受 URL 优先语义影响），且不出现续播提示、不跳转集数。
- 未登录访问 → 所有集无「✓」，且全程零 `/api/me/history` 请求（XHR 钩子实证）。
- 无进度记录的剧 → 全部集无「✓」。

## 七、风险与兜底

| 风险 | 概率 | 兜底 |
|---|---|---|
| 已看推断规则在跳跃式观看场景下标错（如直接 `?ep=3` 看第 3 集，前两集被标已看） | 中 | 可接受：推断式是拍板的取舍；演示按顺序连播路径走即正确；若评委追问，现场讲解「每剧一条最新进度」的数据模型约束即为答案 |
| PlayerPage 调整为「已登录即拉 history」后增加一次请求 | 零 | 未登录零请求保持；已登录每次进播放页多一次轻量查询，演示规模无感 |
| 相对时间格式化边界（跨天/跨年） | 低 | 本地函数兜底为 `yyyy-MM-dd` 绝对日期，不会出现错误文案 |
| 下架剧点击后 404 观感差 | 低 | 属阶段4 拍板的正常口径；「已下架」角标已提前告知用户 |
