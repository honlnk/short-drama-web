## 一、本阶段目标

验收标准一句话：**demo 账号在播放页看片，进度自动上报服务端；换浏览器标签页重新打开该剧，自动从上次集数与进度续播；首页搜索框输入关键词实时过滤短剧；播放页支持滚轮/键盘/手势切集与自动连播。**

达成后，PRD 第八章接口清单中 C 端接口 100% 集齐（`/api/me/progress`、`/api/me/history` 落地），里程碑 6 的「前后端真实打通现场证据」（换标签页进度仍在，PRD PL-04 验收标准原话）就绪；剩余工作只剩 PL-03 已看标记、PL-05 观看历史前端页（等第三阶段 `/mine` 落地后挂载，半天量）、里程碑 7 联调彩排。

### 为什么 worktree 并行

第三阶段正在 main 工作区施工（InteractionController/MeController/DramaService 等未提交改动在途）。本阶段若在同一工作区动工，两个施工方的未提交改动会混在一棵工作树里，门禁回归与提交切分都说不清。worktree 让本阶段拥有独立工作目录与分支，与第三阶段各自跑门禁、各自提交，收口时 git 合并——按上表文件交集分析，合并冲突面最多 `DramaService.java` 一处（若第三阶段收口时动了它），大概率自动合并成功。

**端口冲突规避**：第三阶段占用 8080/3000/3001。本阶段 worktree 自测时后端用 `./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8081`，前端用 `pnpm dev --port 3002`，vite 代理目标用 `VITE_PROXY_TARGET` 环境变量指向 8081——**先检查 vite.config.ts 是否支持该环境变量，不支持则本阶段给 vite.config.ts 加 `process.env.VITE_PROXY_TARGET ?? 'http://localhost:8080'` 一行**（此行与第三阶段无冲突：它不动 vite.config）。

**数据库共享**：worktree 后端连同一个 `short_drama` 库。本阶段不改表结构（ddl-auto=update 无新增），与第三阶段互不干扰。唯一注意：两边后端**不要同时跑**同一份种子判断以外的写逻辑——实际上进度写库按 `(user_id, drama_id)` upsert，演示数据隔离。

## 四、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 进度上报语义 | **upsert**：`PUT /api/me/progress` 按 `(user_id, drama_id)` 唯一索引，存在则更新 episode_id/progress_sec/updated_at，不存在则插入；返回 `{updated: true}` | PRD §6 约束说明明文「每部剧只保留最新一条进度」；唯一索引第一阶段已建 |
| 上报节流 | 播放中每 **5 秒**上报一次 + 切集/暂停/页面卸载（`visibilitychange`）时立即上报一次；未登录不上报、不报错 | 演示规模个位数并发，5s 节流够稀疏；暂停/卸载补刀保证「换标签页进度仍在」的验收场景必现 |
| 进度合法性 | `progressSec` 下限 0，上限该集 `durationSec`（超出截断）；`episodeId` 必须属于该 drama，否则 400 | 防脏数据；集不属于剧说明前端串数据了，明确报错 |
| 观看历史 | `GET /api/me/history` 返回进度列表，按 `updated_at` 倒序，每条含 DramaSummary 全字段 + `episodeId/episodeNo/episodeTitle/progressSec/updatedAt`；**不过滤 OFFLINE 剧**（历史是用户私有数据，下架剧保留记录但前端点击时会撞详情 404，属正常口径） | PRD PL-05「与 PL-04 共用同一份进度数据」；倒序即最近观看在前 |
| 续播入口 | 进播放页时：已登录则 `GET /api/me/history` 找该剧进度，有记录且 `?ep=` 缺省时跳到记录的集并从 `progressSec` 起播；`?ep=` 显式存在则以 URL 为准（用户点选集优先于记忆） | PRD PL-04「再次进入该剧自动从上次集数与进度续播」；URL 优先保证分享链接/选集点击不被覆盖 |
| 起播偏移 | `video.currentTime = progressSec` 在 `loadedmetadata` 后设置；若 progressSec 距片尾 <3 秒则从头播（视为已看完） | 看完的集重进从 0 开始是直觉行为；<3s 阈值防「差一秒没看完永远从结尾起播」 |
| 搜索实现 | `GET /api/dramas?keyword=` 后端 `title LIKE %kw%`（trim 后空串视为无参数）；前端首页搜索框 `onChange` 即搜（受控输入 + 300ms 防抖），搜索结果与分类筛选**共存**（先按 keyword 过滤接口返回，再按分类前端过滤）；空结果提示「没有找到相关短剧」 | PRD PL-06「模糊匹配，空结果有提示」；数据量小，LIKE 够用；防抖防每击键一请求 |
| 搜索框位置 | 首页顶栏右侧（PC）/ 分类条上方独立一行（手机）；不清空分类筛选状态 | PRD 5.1 首页结构含搜索入口；与分类筛选正交互补 |
| 滚轮/键盘切集 | PC/平板：播放区聚焦时滚轮向下=下一集、向上=上一集（节流 500ms），键盘 ↓/→ 下一集、↑/← 上一集；手机：竖向触摸滑动（touchstart/touchend 位移 >50px 判定）；首集往前/末集往后不跳转并提示「已经是第一集/最后一集」；切换复用现有 `selectEpisode`（`setSearchParams`），URL 天然同步 | PRD PL-01「切换流畅，URL 与当前集同步」——现有实现已用 `?ep=` 驱动当前集，手势只是新增触发源 |
| 自动连播 | 视频 `ended` 事件：有下一集则 `selectEpisode(next)` 自动续播（浏览器自动播放策略下 `autoPlay` 已带 muted 风险——**连播时用 `video.play()` 显式触发，被浏览器拦则在播放区叠「点击继续下一集」按钮**）；末集结束停留当前页并提示「已看完最后一集」 | PRD PL-02 验收标准明文「最后一集结束后停留在选集或返回提示」 |
| 进度接口鉴权 | `/api/me/**` 第二阶段已配 `authenticated()`，零改动；控制器沿用第三阶段 MeController 同款 `authUser == null → 401` 防御写法 | 与既有风格一致 |
| worktree 合并时机 | 第三阶段收口（提交上 main）后，本阶段 rebase/merge main 解冲突再合并回 main；若本阶段先完工，**不抢先合并**，等第三阶段落地 | 第三阶段是必含功能收尾，优先级高于加分项；抢先合并会让第三阶段的回归门禁面对陌生改动 |

## 五、工作拆解

3. worktree 内：`apps/web` 与 `apps/api` 依赖安装（`pnpm install`、`./mvnw` 首次拉依赖）。
4. 检查并补 `apps/web/vite.config.ts` 的 `VITE_PROXY_TARGET` 支持（见 §三端口规避）。
5. 验证：`./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8081` 启动成功 + `pnpm dev --port 3002` 首页渲染——与第三阶段服务（8080/3000）**并存不抢端口**。

### 任务 1：后端进度接口（PL-04/05 后端）

新增文件（全部新文件，零改动既有文件）：

1. `repository/WatchProgressRepository.java`：`findByUserIdAndDramaId(userId, dramaId)`、`findByUserIdOrderByUpdatedAtDesc(userId)`。
2. `dto/`：`ProgressReportRequest(episodeId, progressSec)`、`HistoryItem(DramaSummary 全字段平铺 + episodeId/episodeNo/episodeTitle/progressSec/updatedAt)`。
3. `service/ProgressService.java`：
   - `report(userId, dramaId, request)`：剧须存在（**ONLINE/OFFLINE 均可**——用户对下架剧的历史进度仍可写，与历史不过滤 OFFLINE 口径一致；剧不存在 → 404）；episode 须属于该剧否则 400；progressSec 截断到 `[0, episode.durationSec]`；按 `(user_id, drama_id)` 查记录，有则更新四字段（episode/progress/updatedAt），无则新建；`@Transactional`；唯一索引冲突（并发双击）捕获 `DataIntegrityViolationException` 后重查返回，不抛 500。
   - `history(userId)`：`findByUserIdOrderByUpdatedAtDesc` 联表取 Drama + Episode 组装 HistoryItem；Drama/Episode 被删的脏记录跳过（防第三阶段级联删除遗漏）。
4. `controller/ProgressController.java`（`@RequestMapping("/api/me")`，与第三阶段 MeController **同前缀不同文件**，互不包含对方端点）：
   - `PUT /api/me/progress?dramaId=`（body ProgressReportRequest）→ `{updated:true}`
   - `GET /api/me/history` → `List<HistoryItem>`
   - 均沿用 `authUser == null → BusinessException(401)` 防御写法。
5. **单测**：ProgressService——upsert 往返（新建→更新同剧换集）、progressSec 截断、episode 不属于该剧 400、剧不存在 404、history 倒序与脏记录跳过。

**门禁（curl 全绿）**：
- 无 token 调两接口 → 401 JSON（第二阶段鉴权规则回归）。
- demo token 上报剧 1 第 2 集 35s → `{updated:true}`；查库 `watch_progress` 一条记录；再上报同剧第 3 集 8s → 库中仍一条、episode_id 与 progress_sec 已更新（upsert 验证）。
- 上报 progressSec=9999（超时长）→ 库中存截断值；上报不属于该剧的 episodeId → 400。
- `GET /api/me/history` → 含刚上报的剧，字段齐全；再上报剧 2 后 history 倒序剧 2 在前。
- `./mvnw test` 全绿（含新单测）。

### 任务 2：后端搜索 + 前端首页搜索（PL-06）

1. **后端**（改两个既有方法的签名，行为向后兼容）：
   - `DramaService.listOnline(String keyword)`：keyword trim 后非空时走 `dramaRepository.findByStatusAndTitleContainingIgnoreCaseOrderByLikeCountDesc(ONLINE, kw)`（Repository 新增该派生查询），否则走原查询。
   - `DramaController.listOnline(@RequestParam(required=false) String keyword)` 透传。无参调用行为与现状完全一致（回归门禁保底）。
2. **前端**：
   - `api/dramas.ts`：`listDramas(keyword?: string)` 追加可选参数，拼 `?keyword=`（encodeURIComponent）。
   - `HomePage.tsx`：顶部加受控搜索框（占位「搜索短剧」），`onChange` 更新输入态 + 300ms 防抖触发请求；请求与分类筛选各自独立（keyword 走后端、category 走前端过滤）；空结果文案「没有找到相关短剧」（区分于分类空态「该分类暂无短剧」）；搜索框右侧加清空按钮（有内容时显示）。

**门禁**：
- `curl '/api/dramas?keyword=豪门'` → 只含《闪婚老公是豪门》；`?keyword=不存在的词` → 空数组 200；无 keyword → 全量 6 剧（回归）。
- 前端：首页输入「甜」防抖后只剩甜宠分类两部剧；清空恢复全量；搜索态下点分类筛选仍生效（两条件叠加）。
- `pnpm exec tsc -b`（web）通过。

### 任务 3：播放页切集手势 + 自动连播 + 记忆续播（PL-01/02/04 前端）

只改 `PlayerPage.tsx` + 新增 `api/progress.ts`（`reportProgress(dramaId, episodeId, progressSec)`、`getHistory()`）。

1. **进度上报**：
   - 已登录（`useAuth().user` 非空）才启用；`useEffect` 监听播放：`timeupdate` 事件距上次上报 ≥5s 时上报；`pause`/`visibilitychange(hidden)`/切集前各补报一次。
   - 未登录：零调用零提示。
2. **记忆续播入口**：
   - 进播放页：已登录且 `?ep=` 缺省 → `getHistory()` 找该剧记录，有则 `setSearchParams({ep: 记录集数})` 并记 `resumeSec`；`loadedmetadata` 后 `video.currentTime = resumeSec`（距片尾 <3s 归 0）。
   - `?ep=` 显式存在：跳过恢复（URL 优先）。
   - 首屏提示：发生续播时在视频下方短暂显示「已为你续播到第 X 集」（3s 淡出，演示时可指着讲）。
3. **滚轮/键盘/手势切集**：
   - `wheel`（播放区容器，节流 500ms）：deltaY>0 下一集、<0 上一集；`keydown`（页面级）：↓/→ 下一集、↑/← 上一集；`touchstart/touchend`（播放区）：纵向位移 >50px 判定，上滑下一集、下滑上一集。
   - 边界：首集向前/末集向后 → 顶部提示「已经是第一集/最后一集」（复用 hint 模式，1.5s 淡出）。
   - 切集统一走现有 `selectEpisode`（URL 同步天然满足 PL-01 验收）。
4. **自动连播**：
   - `ended`：非末集 → `selectEpisode(下一集)`，`video.play()` 显式触发，被浏览器拦截则播放区中央叠「▶ 继续下一集」按钮（点击即播）；末集 → 提示「已看完最后一集」停留当前页。

**门禁**（浏览器手测 + 脚本断言并用）：
- demo 登录 → 播放剧 1 第 1 集拖到 10s → 等 5s+（或暂停触发上报）→ 关标签页重开该剧播放页（不带 `?ep=`）→ 自动从第 1 集 10s 附近起播并显示续播提示（PRD PL-04 验收场景原样复现）。
- 带 `?ep=3` 进播放页 → 播第 3 集且不恢复进度（URL 优先验证）。
- 播放页滚轮向下 → 切下一集且 URL `?ep=` 同步；键盘 ↑ 回到上一集；首集滚轮向上 → 提示「已经是第一集」。
- 播放到末集结束 → 自动停在末集并提示「已看完最后一集」；非末集结束 → 自动进下一集续播。
- 未登录进播放页 → 不报进度（DevTools Network 无 `/api/me/progress` 请求）、不恢复进度。
- `pnpm exec tsc -b`（web）通过。
