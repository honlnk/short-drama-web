## 一、本阶段目标

验收标准一句话：**访客打开 C 端首页看到真实短剧网格，注册登录后进入详情页看到点赞收藏状态回显，点集进入竖屏播放页正常播放，三档宽度布局无错位；受保护接口无 token 返回 401。**

达成后，演示主路径「首页 → 详情 → 播放」与「注册 → 登录 → 登录态保持」两条线全程真实打通，点赞收藏的按钮 UI 与详情状态回显就位（真正写库属里程碑 4）。

## 二、为什么 2+3 合并（已拍板）

- 里程碑 2 单独交付只有注册登录，评委看到的是「能登录但点不了内容」，价值单薄。
- 里程碑 3 详情页要求「点赞收藏状态随登录用户实时回显」（PRD DR-02），天然依赖 JWT 已通。
- 两个里程碑共享同一批后端工作（Security 改造、JWT、鉴权规则），拆开做会重复搭架子。

## 四、技术决策（已拍死，无开放选择题）

| 决策点 | 定案 | 理由 |
|---|---|---|
| 鉴权方案 | JWT 无状态（jjwt 0.12.6），HS384 签名（52 字符密钥=416bit，jjwt 按位宽自动映射；2026-10-16 修正，原写 HS256 系口径笔误，实际签出即 HS384） | PRD 7.1 定案；免 session 存储，前后端分离标准做法 |
| JWT 密钥 | `app.jwt.secret` 写死 application.yml（本地演示固定串，≥256bit），不拆环境变量 | 与数据库凭据同口径（application.yml 已有的本地演示风格） |
| JWT 过期 | 72 小时 | 演示期间不过期，避免现场重新登录 |
| JWT 载荷 | `sub`=userId、`username`、`role` | 详情页鉴权与角色判断够用即可，不塞冗余字段 |
| 密码加密 | BCrypt（沿用 DataSeeder 已用的 BCryptPasswordEncoder） | PRD US-01 硬性要求 |
| 注册即登录 | 注册成功直接返回 JWT，前端自动进入登录态 | PRD US-01 验收标准明文要求 |
| 详情接口鉴权 | `GET /api/dramas/{id}` 可选登录：带 token 返回 liked/favorited，不带返回 false | 已拍板（本阶段做）；访客可浏览详情，登录用户看到状态回显 |
| 点赞收藏按钮 | 本阶段只做 UI + 未登录引导登录，**不写库**（接口里程碑 4 才做） | 互动闭环是里程碑 4，本阶段不越界 |
| 搜索（PL-06） | **本阶段不做**，首页只做分类筛选；搜索挪里程碑 6 | 已拍板；把时间省给播放页 |
| 前端路由 | react-router-dom v7（已在 package.json） | 已装，直接用 |
| 全局状态 | React Context（AuthContext），不引 zustand/redux | 演示规模小，Context 够用，少一个依赖 |
| token 存储 | localStorage（key=`token`） | PRD US-03 会话保持的标准做法 |
| 播放页切集 | 本阶段只做「点选集列表跳集」+ URL `?ep=` 同步；滑动/滚轮切集（PL-01）与自动连播（PL-02）属里程碑 6 | 播放页先把「能播、能跳集」做扎实，手势后补 |

## 五、工作拆解

### 任务 1：后端 JWT 鉴权（里程碑 2 后端）

新增 `security/` 包与认证接口，改造 SecurityConfig。

1. **配置**：`application.yml` 追加：

   ```yaml
   app:
     jwt:
       secret: short-drama-local-demo-secret-key-please-change-in-prod
       expire-hours: 72
   ```

2. **新增 `security/` 包**（`com.shortdrama.api.security`）：
   - `JwtService`：`generateToken(User)`（载荷 sub/username/role，HS384——416bit 密钥自动映射，72h）、`parseToken(String)`（返回 Claims，过期/非法抛异常）。
   - `JwtAuthFilter extends OncePerRequestFilter`：从 `Authorization: Bearer <token>` 解析，构造 `UsernamePasswordAuthenticationToken`（authorities 含 `ROLE_<role>`）塞入 SecurityContext；无 token 或非法则放行（由授权规则兜底 401）。
   - `UserDetailsServiceImpl implements UserDetailsService`：`loadUserByUsername` 走 UserRepository；password 用实体的 `password` 字段（BCrypt 摘要）。
   - `AuthUser`（或直接用 UserDetails）：供 `@AuthenticationPrincipal` 注入当前登录用户 id。

3. **改造 `SecurityConfig`**（替换现有全量放行）：
   - 公开：`/api/auth/**`、`GET /api/dramas`（列表）、`GET /api/dramas/{id}`、`GET /api/dramas/{id}/episodes`、`/api/ping`、`/uploads/**`。
   - 登录：`POST /api/dramas/*/like`、`POST /api/dramas/*/favorite`、`/api/me/**`（规则先配好，接口里程碑 4 实现）。
   - 管理员：`/api/admin/**` 需 `hasRole("ADMIN")`（规则先配好，接口里程碑 5 实现）。
   - 无状态：`SessionCreationPolicy.STATELESS`，关闭 CSRF（纯 API + JWT，无表单）。
   - 401 处理：`AuthenticationEntryPoint` 返回统一 JSON `{code:401, message:"未登录或登录已过期", data:null}`，Content-Type `application/json;charset=UTF-8`。

4. **新增认证接口**：
   - `dto/`：`RegisterRequest(username, password)`、`LoginRequest(username, password)`、`AuthResponse(token, user: UserInfo)`、`UserInfo(id, username, nickname, role)`。用户名/密码 `@NotBlank`，用户名长度 2~50。
   - `AuthService`：`register`（用户名唯一校验，重名抛业务异常「用户名已被注册」；BCrypt 加密入库；role=USER；nickname 默认同 username）、`login`（查用户 + `matches` 校验，失败抛「用户名或密码错误」）。
   - `AuthController`：`POST /api/auth/register`、`POST /api/auth/login`（均返回 AuthResponse）；`GET /api/auth/me`（登录，返回当前 UserInfo，供前端刷新校验登录态）。
   - 全局异常：`@RestControllerAdvice` 统一捕获业务异常与校验异常，返回 `{code, message}` 结构（与 PingController 的 `code/message/data` 风格一致）。

**门禁（curl 全绿）**：
- `POST /api/auth/register` 新用户 → 200 返回 token；重复注册 → 明确错误提示。
- `POST /api/auth/login` demo/demo123 → 200 返回 token；错误密码 → 「用户名或密码错误」。
- 带 token `GET /api/auth/me` → 200；不带 token → 401 JSON；伪造/过期 token → 401。
- `GET /api/dramas` 不带 token 仍可访问（公开接口不回退）。

### 任务 2：后端详情与剧集接口（里程碑 3 后端）

`DramaController` 现有列表接口不动，新增两个：

1. `GET /api/dramas/{id}` — 短剧详情（可选登录）：
   - DTO `DramaDetail`：DramaSummary 全部字段 + `episodes`（剧集列表）+ `liked`、`favorited`（布尔）。
   - 鉴权：`JwtAuthFilter` 已解析 token 则 SecurityContext 有用户；控制器取当前用户 id（无则为 null），据此查 UserLike / Favorite 是否存在，填充 liked/favorited。
   - 剧集按 `episodeNo` 升序返回。
   - 剧不存在 → 404；OFFLINE 剧 → 404（C 端不可见）。
2. `GET /api/dramas/{id}/episodes` — 剧集列表（公开）：
   - DTO `EpisodeSummary(id, episodeNo, title, videoUrl, durationSec)`，按 `episodeNo` 升序。
   - 供播放页选集用；videoUrl 为相对路径 `/uploads/videos/drama-xx/ep-xx.mp4`，前端经 Vite 代理访问。

新增 `FavoriteRepository`、`UserLikeRepository`（`existsByUserIdAndDramaId` 查询）。

**门禁**：
- `curl /api/dramas/1` → 含 episodes 与 liked/favorited=false（不带 token）。
- 带 demo token → liked/favorited 反映真实（此时均无，应为 false）。
- `curl /api/dramas/1/episodes` → 4 集升序，videoUrl 路径正确。
- 浏览器访问返回的 videoUrl（经 `http://localhost:8080/uploads/...`）可播放。

### 任务 3：C 端认证链路（里程碑 2 前端）

`apps/web` 从单页脚手架改造为带路由与全局登录态的应用。

1. **基础设施**（`src/`）：
   - `api/client.ts`：axios 实例 `baseURL:''`（走 Vite 代理）；请求拦截器从 localStorage 读 token 塞 `Authorization`；响应拦截器遇 401 清 token + 跳 `/login?from=<当前路径>`。
   - `api/auth.ts`：`register/login/getMe` 三个请求函数 + TS 类型（对齐后端 AuthResponse/UserInfo）。
   - `store/AuthContext.tsx`：`AuthProvider` 持有 `user`、`token`、`login()`、`logout()`、`ready`（初始化标记）；挂载时若 localStorage 有 token 则调 `/api/auth/me` 校验并回填 user，失败则清 token；`useAuth()` hook 导出。
   - `router/index.tsx`：`createBrowserRouter`，路由表：`/`（HomePage）、`/drama/:id`（DramaDetailPage）、`/drama/:id/play`（PlayerPage，读 `?ep=`）、`/login`、`/register`；`RequireAuth` 守卫（未登录跳 `/login`）——本阶段点赞收藏用「点击时判断」而非整页守卫，守卫组件先备好供里程碑 4 用。
   - `App.tsx` 改为 `RouterProvider` 挂载点，外包 `AuthProvider`；删除脚手架的 ping 占位 UI（首页由任务 4 实现）。

2. **页面**：
   - `LoginPage`：用户名+密码表单、提交 loading、错误提示（后端返回的 message）；成功后 `login(token,user)` 并跳回 `?from=` 或首页；页面给出 `demo/demo123` 与 `admin/admin123` 快捷填充按钮（演示友好）。
   - `RegisterPage`：用户名+密码+确认密码（前端二次校验一致）、重名错误提示；成功后自动登录跳首页；链接到登录页「已有账号去登录」。

**门禁**：注册 → 自动登录 → 刷新页面（AuthContext 经 getMe 恢复）登录态仍在 → 退出登录 → 再访问需登录操作被引导到登录页。`tsc -b` 通过。

### 任务 4：C 端首页 + 详情 + 播放（里程碑 3 前端）

1. **首页 `HomePage`**（替换脚手架占位页）：
   - 顶部：分类筛选条（全部/甜宠/都市/逆袭/古装/悬疑），选中态高亮；点击前端过滤（数据量小，无需后端筛选参数）。
   - 封面网格：`grid-cols-2 md:grid-cols-4 xl:grid-cols-6`（对应手机 2 列 / 平板 4 列 / PC 6 列，符合 PRD 5.3 的区间）。
   - 卡片：封面图（`<img src={coverUrl}>` 经代理）、剧名、集数、点赞数（对齐 DramaSummary 字段）；点击跳详情。
   - 数据：`GET /api/dramas`，loading + 空态 + 失败重试提示。
2. **详情页 `DramaDetailPage`**：
   - 布局：手机单列；平板/PC 封面左 + 信息右（`md:flex-row`）。
   - 内容：剧名、分类、简介、总集数、点赞数；点赞/收藏按钮（显示 liked/favorited 状态；**点击时**：未登录跳登录页，已登录提示「里程碑 4 实现」占位，不写库）。
   - 选集列表：集数按钮网格，点击跳 `/drama/:id/play?ep=<episodeNo>`。
   - 数据：`GET /api/dramas/{id}`。
3. **播放页 `PlayerPage`**：
   - 竖屏视频：`<video controls autoPlay>`，宽 `min(100vw, 400px)`、高按 9:16 比例（`aspect-[9/16]`），居中；任何宽度不拉宽不裁切。
   - 布局：手机全屏沉浸；平板/PC「中央竖屏播放区 + 右侧信息栏」（剧名/简介/选集/点赞按钮）双栏（`md:flex-row`）。
   - 选集：读 `?ep=` 定位当前集（默认第 1 集），点击选集切换并更新 URL；video `key` 随集变化强制重载。
   - 数据：`GET /api/dramas/{id}/episodes`（+详情取剧名）。

**门禁**：
- 首页网格渲染 6 部真实剧，封面/剧名/集数/点赞数来自接口，无写死。
- 首页分类筛选正确（点「悬疑」只剩悬疑剧）。
- 首页 → 详情 → 点第 2 集 → 播放页播第 2 集，URL 含 `?ep=2`；浏览器刷新仍停在第 2 集。
- 三档宽度（拖窗口跨 768 / 1280 断点）布局无错位、无横向滚动条；视频始终 9:16。
- `tsc -b` 通过；断网（停外网）演示路径无外部资源缺失。
