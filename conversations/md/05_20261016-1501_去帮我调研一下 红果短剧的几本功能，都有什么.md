# 红果短剧功能调研

**产品定位**：字节跳动（抖音集团）旗下的免费短剧 App，主打「海量短剧免费看」，靠广告变现（IAA 模式）而不是付费解锁——这是它区别于绝大多数付费短剧平台的最大特点。竖屏、单集 1~3 分钟、一部剧几十上百集、节奏快爽点密。

## 一、核心观看功能（C 端主路径）

| 功能 | 说明 |
|---|---|
| 沉浸式竖屏播放 | 类似抖音的全屏竖屏播放，上下滑动切换剧集/短剧 |
| 选集 | 一部短剧分几十~上百集，播放页可拉出选集列表跳集 |
| 自动连播/记忆续播 | 看完一集自动下一集；下次打开自动从上次进度继续 |
| 倍速播放 | 0.75x / 1x / 1.25x / 1.5x / 2x |
| 清晰度切换 | 标清/高清等 |
| 投屏 | 投到电视大屏看 |

## 二、内容发现功能

| 功能 | 说明 |
|---|---|
| 首页推荐 feed | 个性化推荐流，根据观看历史和偏好推送 |
| 分类/剧场频道 | 按题材分栏：都市、甜宠、逆袭、战神、古装、悬疑、穿越、重生、萌宝等 |
| 排行榜/热榜 | 热播榜、新剧榜、飙升榜 |
| 搜索 | 按剧名/关键词搜索，热门搜索词推荐 |
| 每日更新 | 新剧、更新提醒 |

## 三、用户体系与互动功能

| 功能 | 说明 |
|---|---|
| 注册/登录 | 手机号验证码为主，支持抖音账号一键登录 |
| 点赞 | 给剧点赞 |
| 收藏/追剧 | 收藏整部剧，加入「我的追剧」片单 |
| 观看历史 | 历史记录列表，点击直接续播 |
| 评论/互动 | 剧集评论区、分享给好友 |
| 签到/金币任务 | 看剧领金币、每日签到，金币可提现（网赚激励，是拉新留存核心手段） |

## 四、其他模块

- **扩展内容**：后期版本整合了电影、电视剧、小说、听书、漫画等内容（和番茄系打通）
- **个人中心**：我的追剧、收藏、历史、金币/钱包、设置
- **商业化**：激励视频广告（看广告解锁/赚金币）、信息流广告

## 五、对照我们的题目（REQUIREMENTS.md）

题目要求的「简化版」必做项是：**注册登录、短剧展示、点赞、收藏、管理后台（内容增删改查）**。从上面调研看，演示时最值得做的「加分项」按性价比排序：

1. **竖屏沉浸式播放 + 上下滑动切集** —— 最像红果，演示效果最炸，Web 上用 video + 滚动捕捉能实现
2. **选集 + 自动连播 + 记忆续播** —— 实现成本低，播放进度存数据库正好体现「前后端真实打通」
3. **分类 + 搜索 + 热榜** —— 就是列表页加筛选条件，SQL 层面很简单
4. **观看历史** —— 和记忆续播是同一份数据，顺手做
5. **管理后台**：剧/集两级内容管理（增删改查 + 封面上传 + 视频 URL + 上下架）

评论、金币提现、投屏这类属于重运营/重客户端的功能，Web 简化版不建议做。

调研结论就这些。如果你认可这个范围，下一步我可以帮你把功能清单落成开发计划（后端 Java + 前端 React 的模块拆分和数据库设计），随时可以开工。

## 功能范围建议

**P0 — 必做（题目硬性要求，缺一个就是没完成）**

| 功能 | 说明 |
|---|---|
| 注册 / 登录 | JWT 鉴权 + BCrypt 密码加密，预置普通用户和管理员两个初始账号 |
| 短剧内容展示 | 首页推荐列表（封面卡片流）+ 播放页，剧/集两级数据 |
| 点赞 / 收藏 | 对整部剧点赞、收藏，播放页和详情处可操作 |
| 管理后台 | 短剧 + 剧集的增删改查（标题、简介、封面、分类、视频 URL、上下架） |
| 种子数据 | 启动自动初始化 4~6 部短剧、每部 3~5 集，演示零造数据 |

**P1 — 强烈建议做（便宜且演示效果最炸）**

| 功能 | 理由 |
|---|---|
| 竖屏沉浸式播放 + 上下滑动切集 + 自动连播 | 这是"像红果"的灵魂，Web 端用滚动捕捉能实现，评委一眼认得出 |
| 选集列表 + 记忆续播 | 播放进度上报存数据库，正好现场证明"前后端真实打通"，讲解时是个硬证据 |
| 分类筛选 + 搜索 | 列表页加查询条件而已，SQL 层面成本极低 |
| 观看历史 | 和记忆续播同一份数据，顺手输出一个"我的"页面 |

**P2 — 有时间再碰**：热榜（按点赞/播放排序，一个 ORDER BY）、评论。

**明确不做**：金币/签到/提现、个性化推荐算法、投屏、下载、第三方登录、付费解锁——都是重运营或重客户端能力，和演示主线无关。

## 技术骨架建议

- **后端**：Spring Boot 3 + JPA + Maven，JWT 鉴权
- **数据库**：默认 H2 嵌入式文件库（`jdbc:h2:file:./data`），一条命令启动、零外部依赖，现场演示最稳；留一个 MySQL profile 备选，讲解时说"可切换"还是加分项
- **前端**：Vite + React + React Router。C 端做成手机宽度的竖屏页面（演示时浏览器开手机模拟视图，就是 App 的感觉）；管理后台用 Ant Design 快速搭，桌面宽度
- **视频源**：种子视频下载到后端静态目录本地播放——**现场网络不可控，这是演示翻车的最大风险点，必须本地兜底**，封面图同理

## 开发顺序（演示路径优先）

1. 脚手架 + 数据库 schema + 种子数据 → 先让"启动就能看到内容"成立
2. 注册登录
3. 首页列表 + 播放页（核心演示路径）
4. 点赞收藏
5. 管理后台 CRUD
6. P1 加分项：滑动切集、记忆续播、搜索分类
7. 全流程联调 + 演示彩排

裁剪逻辑：如果现场时间比预期紧，P1 里先砍搜索分类，保住"滑动切集 + 记忆续播"——这两个是演示时最值钱的功能。
