## 我的建议

### 方案 A：不用 RuoYi-Plus，纯手写（推荐）

```
apps/
├── api/          # Spring Boot 3 + JPA + H2（轻量）
├── web/          # React 用户端
└── admin/        # React 管理后台（简单页面即可）
```

**理由：**
- 短剧业务简单：短剧 CRUD + 用户点赞收藏
- RuoYi 的 80% 功能你用不上（工作流、代码生成、多数据源、分布式锁...）
- 手写更快：JPA 自动生成表，H2 内嵌启动
- 演示更流畅：零外部依赖，评委体验好

### 方案 B：只用 RuoYi-Plus 的管理后台

```
apps/
├── api/          # Spring Boot 3 纯手写（短剧业务 API）
├── admin-api/    # RuoYi-Vue-Plus（用户体系 + 权限）
├── admin/        # React 管理后台（对接 RuoYi API）
└── web/          # React 用户端
```

**问题：** 两个后端服务，复杂度翻倍，演示容易出问题。

### 方案 C：全套 RuoYi-Vue-Plus 6.0

```
apps/
├── admin-api/    # RuoYi-Vue-Plus 6.0（含业务模块）
├── admin/        # React 管理后台（自己写，对接 RuoYi）
└── web/          # React 用户端（对接 RuoYi API）
```

**问题：** 
- 需要理解 RuoYi 的模块结构（`ruoyi-modules/xxx`）
- 需要配置 MySQL（H2 支持不完善）
- 前端需要对接 RuoYi 的接口规范（`code/msg/data` 格式）
- 开发周期变长，演示风险高
